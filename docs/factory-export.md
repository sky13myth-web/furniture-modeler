# Передача заказа раскройной фабрике

Во вкладке **Раскрой → Для фабрики** выберите весь проект или отдельный шкаф в поле **Комплект для**. Для обычного заказа мастерской нажмите **Заказ мастерской Excel**: получите `kesim-listesi.xlsx` с отдельной вкладкой каждого материала, декора и толщины. Первые две колонки — ширина A и длина B заготовки, затем количество, код и название детали, шкаф, четыре кромки, текстура и форма. Материал, толщина и размеры исходного листа указаны в заголовке вкладки; дополнительные вкладки содержат список листов и последовательность резов. Язык описаний и чертежей берётся из настройки языка документов; по умолчанию турецкий. Таблица фиксирует заголовки при прокрутке и позволяет фильтровать детали.

В браузере после подготовки появляется карточка с именем, размером файла и ссылкой **Сохранить файл**. В установленной Windows-программе открывается обычное окно сохранения; карточка показывает фактический путь только после завершения записи и позволяет открыть папку. Закрытие окна экспорта не убирает результат скачивания.

В архиве:

| Файл | Назначение |
| --- | --- |
| `kesim-listesi.xlsx` | Отдельные таблицы по материалу, декору и толщине: числовые размеры заготовки в первых колонках, количество, Pxxxx, деталь, шкаф, четыре кромки, текстура и форма. Дополнительные вкладки — листы и резы. |
| `kesim-listesi.csv` | Общая читаемая ведомость с материалом, декором, толщиной и отдельными готовыми размерами. Заголовки всех читаемых таблиц — турецкие / русские / английские. |
| `cut-list.csv` | Детали без итоговых строк: ID, материал и декор, толщина, количество, размеры распила и готовые размеры, текстура, поворот, четыре торца, ссылка на DXF. |
| `materials.csv` | Коды материалов, фактическая толщина и размеры листов. |
| `dxf/Pxxxx.dxf` | Один замкнутый контур каждой заготовки, AutoCAD 2000, слой CUT, масштаб 1:1 в мм. |
| `dxf/sheets-all.dxf`, `dxf/sheets/sheet-xxx.dxf` | Фактические листы раскроя с контурами заготовок 1:1 в мм и Pxxxx. Первый файл содержит все листы, разнесённые вправо; отдельные файлы содержат один лист без сдвига. |
| `sheet-layout.csv` | Исходные и размещённые размеры, поворот и координаты каждой детали на листе от верхнего левого угла. |
| `cuts/regions.csv` | Прямоугольники участков: размеры, координаты, родитель, состояние, рез и дочерние участки. |
| `cuts/cut-sequence.csv`, `cuts/cut-sequence.html` | Нумерованные проходы пилы, ширина пропила, исходные и полученные участки листа; HTML можно печатать. |
| `cuts/cuts-all.dxf`, `cuts/sheet-xxx-cuts.dxf` | Отдельные оси проходов пилы в CAD, с номерами Cxxx. |
| `parts/Pxxxx.svg` | Размеры, кромимые стороны, направление текстуры и тот же ID детали. |
| `assembly.html` | Сборочные чертежи и ведомости для печати / сохранения PDF в браузере. |
| `assembly/cabinet-xxx.html` | Подробный печатный комплект каждого шкафа с видами, сборочной схемой и номерами деталей. |
| `document-set.csv` | Код ревизии проекта, дата выпуска в часовом поясе Турции и выбранный шкаф / весь проект. |
| `cutting-reference.html`, `cutting/sheet-xxx.svg` | Печатные карты того же гильотинного плана с ID деталей; отдельная последовательность резов находится в cuts/. |
| `README.txt` | Правила импорта на языке документов. |
| `checks.txt` | Замечания проверки, если они есть. |

Кнопка **Листы с деталями DXF** сохраняет один `sheets-all.dxf` с фактической раскладкой. Полный комплект содержит также последовательность резов и отдельные контуры деталей. Количество деталей берётся из CSV, а не из числа DXF-файлов. Один ID обозначает одну деталь и остаётся одинаковым в чертежах, ведомости и на карте раскроя.

Для небольшой мастерской обычно удобнее начать с таблицы размеров и кромок. Например, [BAK CNC принимает список размеров и количества через сайт или Excel](https://bakcnc.com/hizmetlerimiz), а [Mizan Ebatlama просит указать материал, толщину, декор, текстуру и кромление](https://www.mizanmobilya.com/ebatlama/hizmet/plaka-ebatlama-ve-kesim). Для фигурных деталей приложите DXF. Условия конкретной мастерской могут отличаться; в таблице явно разделены размеры распила и готовые размеры, чтобы получатель выбрал свою базу.

При экспорте отдельного шкафа номера Pxxxx и номер шкафа сохраняются из общего проекта. Например, второй шкаф остаётся `cabinet-002`, а его детали не перенумеровываются с P0001. Геометрическая ошибка соседнего шкафа не блокирует правильный выбранный шкаф; общие ошибки настроек, структуры или материалов продолжают проверяться. Кнопка **Схема сборки / Печать** открывает тот же выбранный комплект для просмотра и печати.

Печатные карты раскроя используют отдельные листы A4. Узкие детали получают выносной номер и строку размеров в таблице. Плотная карта разбивается на несколько листов без уменьшения букв. Номера, размеры и кромки остаются различимыми при чёрно-белой печати.

## Размеры и кромка

CSV: UTF-8 с BOM, разделитель `;`, десятичная точка, строки CRLF. Первая строка — заголовки; последующие строки имеют одинаковый набор колонок. Пропил и поля из настроек проекта учитываются при размещении и расчёте проходов пилы; они не прибавляются к размерам деталей.

Используйте **одну** из двух пар размеров:

- `CUT_LENGTH_MM` / `CUT_WIDTH_MM` — заготовка для распила, кромка уже вычтена. Автоматическое уменьшение размера на кромку в принимающем ПО должно быть выключено.
- `FINISHED_LENGTH_MM` / `FINISHED_WIDTH_MM` — готовая деталь. Подходит, когда фабрика принимает готовые размеры и сама рассчитывает заготовку по согласованному кромлению.

Пример: готовая полка 600 мм, передняя кромка 1 мм, размер распила 599 мм. Если из уже уменьшенных 599 мм снова вычесть кромку, получится ошибочная заготовка 598 мм. Поля `INFO_EDGE_*` называются информационными именно для того, чтобы их не приняли за указание повторно уменьшить `CUT_*`.

| Поле | Что означает |
| --- | --- |
| `LENGTH` | B — высота на чертеже детали. |
| `WIDTH` | A — ширина на чертеже. Размеры не сортируются по большей стороне. |
| `INFO_EDGE_LENGTH_1_MM` / `_2_MM` | Левый / правый торец SVG, параллельно B. |
| `INFO_EDGE_WIDTH_1_MM` / `_2_MM` | Верхний / нижний торец SVG, параллельно A. |
| `GRAIN_AXIS=LENGTH` | B сохраняется вдоль оси `SHEET_LENGTH_MM` листа. |
| `GRAIN_AXIS=NONE` | Направленной текстуры нет. |
| `ROTATABLE=1` / `0` | Поворот заготовки на 90° разрешён / запрещён. |

Толщина кромки указана в мм, 0 означает отсутствие кромки. Физические стороны дополнительно описаны в `EDGE_DESCRIPTION` и выделены в SVG. У фигурной детали четыре поля относятся к её наружным границам; внутренние края выреза не включаются в них автоматически.

Отдельный `dxf/Pxxxx.dxf` отражает ось Y относительно экранного SVG: верхний торец находится при Y=`CUT_LENGTH_MM`, нижний — при Y=0. Он содержит только замкнутый контур CUT, без размерных линий, сверловки, кромления и компенсации фрезы.

## Листы и проходы пилы

Экран раскроя, DXF листов, таблицы Excel и файлы резов используют один гильотинный план. Каждый проход пересекает весь указанный прямоугольный участок, отделённый предыдущими проходами. Листы разделены по материалу и фактической толщине; заготовки не пересекаются и имеют зазор для заданного пропила. Направление текстуры и запрет поворота учитываются при размещении.

`sheet-layout.csv` и `cuts/cut-sequence.csv` используют начало в **верхнем левом углу исходного листа**, X вправо, Y вниз. `RAW_WIDTH_A_MM` и `RAW_LENGTH_B_MM` сохраняют исходную базу детали; `PLACED_*` учитывают поворот на 90°. Координаты `START_*` / `END_*` обозначают **ось полотна пилы**, а `SAW_KERF_MM` — его ширину. `SEQUENCE` начинается с 1 на каждом листе; `PARENT_REGION_ID` и `RESULT_REGION_IDS` связывают проход с участками из `cuts/regions.csv`. Для отделённой полосы указаны размеры исходного участка, `BLADE_CENTER_OFFSET_MM` от его левого или верхнего края и `RETAINED_SIZE_MM` — размер сохраняемой части до ближней грани пропила. Последний отличается от оси полотна на половину ширины пропила. Читаемые HTML и Excel показывают короткие Cxxx/Rxxxx внутри листа Sxxx; CSV сохраняет полные ID. Для обрезки небольшого поля полоса пропила может частично выходить за край листа.

В DXF ось Y отражена относительно таблиц: CAD Y = длина листа − табличная Y. В общем файле листы дополнительно сдвинуты по X на ширину предыдущего листа + 100 мм; отдельных файлов этот сдвиг не касается. Слои `Sxxx_PART_Pxxxx` — конечные контуры деталей; `Sxxx_STOCK`, `Sxxx_LABELS` и `Sxxx_BLANK_Pxxxx` справочные. BLANK обозначает прямоугольную заготовку фигурной детали: прямые резы отделяют её, а вырез обрабатывают отдельно по `dxf/Pxxxx.dxf`. Справочные границы и надписи нельзя импортировать как дополнительные контуры реза. В `cuts/*.dxf` сущности LINE — оси проходов, а не замкнутые контуры для фрезеровки.

Последовательность предназначена для проверки оператором. Принимающая мастерская проверяет допустимость порядка, возможности своей пилы и преобразует данные в формат станка. Эти файлы не являются G-code или универсальной управляющей программой CNC.

## Совместимость

Это комплект задания на изготовление. Для фактического импорта оператор сопоставляет колонки с шаблоном своей программы. Например, [HOMAG intelliDivide поддерживает CSV и таблицы, а при первом импорте предлагает настроить шаблон](https://docs.homag.cloud/v1/docs/en/intellidivide-tutorial-importing-data). У [SCM Optiwise возможности фиксированного и настраиваемого импорта зависят от версии](https://www.scmgroup.com/en_IN/scmwood/products/maestro-digital-systems/software.c102273/beam-saw.102278).

Согласование базы размеров необходимо: [турецкая BAK CNC требует готовые размеры и вычитает кромку при подготовке заказа](https://bakcnc.com/sss). В этом случае получатель выбирает `FINISHED_*`. Её [шестиколонный шаблон](https://bakcnc.com/assets/templates/cnc_ebatlama_sablonu.csv) объединяет кромки попарно и не передаёт все четыре отдельные стороны нашего проекта, поэтому автоматическая совместимость с ним не заявляется.

DXF использует [замкнутую LWPOLYLINE по спецификации Autodesk](https://help.autodesk.com/cloudhelp/2024/ENU/AutoCAD-DXF/files/GUID-748FC305-F3F2-4F74-825A-61F04D757A50.htm) и [единицы `$INSUNITS=4` — миллиметры](https://help.autodesk.com/cloudhelp/2021/ENU/AutoCAD-DXF/files/GUID-A85E8E67-27CD-4C59-BE61-4DC9FADBE74A.htm). Фабрика проверяет предложенную последовательность и формирует программу конкретного станка в своём ПО. Фигурный вырез требует соответствующей операции после прямоугольного раскроя либо подходящего CNC.

Экспорт блокируется при ошибках проекта, неположительных размерах, неверном контуре, несовпадении толщины детали с выбранным листом и деталях, не помещающихся на лист. Опциональная [сверловка корпуса под конфирматы](drilling.md) выгружается отдельным CSV или ZIP со схемами; контуры CUT в DXF остаются только контурами реза. Монтажные отверстия конкретных петель и направляющих не моделируются. Конструкция ящика здесь имеет накладное дно и боковые направляющие; размеры для пазового дна или скрытых направляющих требуют отдельной схемы.

Образцы: `examples/wardrobe-factory.csv`, `examples/wardrobe-factory.zip`, `examples/wardrobe-part-P0001.dxf`, `examples/wardrobe-kesim-listesi.xlsx`, `examples/wardrobe-sheets-all.dxf`, `examples/wardrobe-cuts-all.dxf`, `examples/wardrobe-cut-sequence.csv`, `examples/wardrobe-cut-sequence.html`, `examples/wardrobe-sheet-layout.csv`. Обновление: `node scripts/export-factory-example.mjs`.
